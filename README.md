# 社内読み取りツール（ランチャー）手順書

社内の読み取りツール（Apps Script のウェブアプリ。経理・資産管理・植物管理など）や関連するシートを、1つのアイコンからまとめて開くためのアプリ（PWA）です。分類ごとに見出しで分けて表示されます。ランチャー自体は「入口」だけを持ち、各ツール・シートはブラウザで開きます。

## 1. 事前準備（初回のみ）

1. 各ツールの Apps Script エディタで「デプロイ」→「デプロイを管理」を開き、「ウェブアプリ」の URL（末尾が `/exec`）を控えておく。エディタの URL（`/edit` で終わるもの）とは別物です。
2. 同じ画面の鉛筆アイコン（編集）で、「アクセスできるユーザー」が社内の組織内（thomas-gr.com のユーザー）になっているか確認する。ランチャーのページは誰でも見られるため、ここがツールを守る鍵になります。
3. PowerShell で次の2行を1行ずつ実行し、終わったら PowerShell を開き直す。
   ```
   winget install --id Git.Git -e
   ```
   ```
   winget install --id GitHub.cli -e
   ```
4. GitHub のアカウントが無い場合は github.com で無料アカウントを作る。

## 2. セットアップと公開

ダウンロードした `ocr-launcher-setup.ps1` を、PowerShell で次の1行で実行します。ダウンロードフォルダにある一番新しいセットアップを選んで実行するコマンドです。

```
powershell -ExecutionPolicy Bypass -File (Get-ChildItem "$HOME\Downloads\ocr-launcher-setup*.ps1" | Sort-Object LastWriteTime | Select-Object -Last 1).FullName
```

同じ名前のファイルがダウンロードフォルダに既にあると、ブラウザは新しいほうを `ocr-launcher-setup (1).ps1` のような名前で保存します。上のコマンドなら、名前に関係なく一番新しいものが実行されます。実行すると最初に「セットアップ（日付 版）」と表示されるので、新しい版が動いていることを確認できます。

スクリプトが次の順に進めます。

1. ツール一覧（`apps.js`）を確認する。2回目以降は、入力済みの内容（URL や手直しした説明文）を残したまま、空の URL を補い、新しい項目があれば追加してよいかを確認する
2. 「ドキュメント」の中に `ocr-launcher` フォルダを作り、必要なファイルを作成する
3. 項目ごとに URL を確認してくるので、変える場合だけ貼り付けて Enter（そのままでよければ Enter。まだ無いツールは空のまま Enter で「準備中」になる）
4. 「公開しますか？」に `Y` と答えると GitHub に公開する。初回は GitHub へのログインを求められるので、画面に出るコードをブラウザに貼り付けて承認する
5. 最後に「配布用 URL」が表示されれば完了（反映まで数分かかることがあります）

## 3. 作成されるファイル

`ドキュメント\ocr-launcher` フォルダに、次のファイルが作られます。ファイル名は PWA の決まりに合わせているため、変更しないでください。

| ファイル | 役割 | 編集 |
|---|---|---|
| `apps.js` | ツール・シートの一覧（分類・アイコン・名前・説明・URL） | ここだけ編集します |
| `publish.ps1` | 公開・更新用のスクリプト | 不要 |
| `index.html` | ランチャーの画面本体 | 不要 |
| `manifest.webmanifest` | アプリ名・アイコンの設定 | 不要 |
| `sw.js` | オフラインでも画面を開けるようにする仕組み | 不要（更新時に自動で書き換わります） |
| `README.md` | この手順書 | 不要 |
| `icons\`（5点） | ホーム画面・タブに出るアイコン画像 | 不要 |

## 4. iPhone 実機での確認（社内配布の前に）

Safari で配布用 URL を開き、共有ボタン →「ホーム画面に追加」でアイコンを作ります。そのアイコンから起動してツールを1つ開き、Google ログインができるか、領収書の撮影ができるかを確かめてください。

ホーム画面から起動したアプリでは、ツールが Safari 本体ではなくアプリ内のブラウザ画面で開く場合があり、初回に Google ログインを求められる可能性があります。この点は未確認のため、必ず実機で確認してください。

## 5. 社内への配布

配布用 URL を利用者に共有します。インストール方法は次のとおりです。

| 端末 | 手順 |
|---|---|
| iPhone・iPad | Safari で開き、共有ボタン →「ホーム画面に追加」 |
| Android | Chrome で開き、画面下の「このアプリをインストール」ボタン |
| PC | Chrome か Edge で開き、画面下の「このアプリをインストール」ボタン |

## 6. 更新のしかた

URL の変更やツール・シートの追加は、`ドキュメント\ocr-launcher\apps.js` をメモ帳で編集して保存し、そのフォルダで次の1行を実行します。

```
powershell -ExecutionPolicy Bypass -File "$HOME\Documents\ocr-launcher\publish.ps1"
```

画面を最新にするための設定（`sw.js` の `CACHE_VERSION`）も自動で更新されます。変更がなければ何もしません。

ツールやシートを追加するときは、`apps.js` の `{ ... }` のかたまりを1つ複製して書き換えてください。項目の意味は次のとおりです。

| 項目 | 内容 |
|---|---|
| `category` | 分類の見出し。同じ文字のツールは同じ見出しの下にまとまります（例：`経理`・`資産管理`・`植物管理`） |
| `icon` | アイコン。`receipt`（領収書）・`card`（カード）・`tag`（ラベル）・`leaf`（植物）・`sheet`（表）・`doc`（書類）から選びます |
| `name` / `description` | 名前と1行の説明 |
| `audience` | 対象者の表示（例：`経理担当者向け`）。不要なら空 `""` |
| `url` | ツールは `/exec` で終わるウェブアプリ URL、シートなどはそのページの URL。空 `""` なら「準備中」 |

セットアップ（`ocr-launcher-setup.ps1`）を新しい版で実行し直した場合も、入力済みの URL や手直しした説明文はそのまま残ります。新しい版で増えた項目は、追加してよいかを確認してから加えます。

## 7. 公開範囲についての注意

GitHub Pages で公開したページは、リポジトリを非公開にしても、ページ自体はインターネット上の誰でも閲覧できます（閲覧を社内に限定できるのは GitHub Enterprise Cloud の契約がある場合のみ）。ランチャーにはツールへのリンクしか載っていないため、各ツールのアクセスが社内に限定されていれば中身は守られます。

ランチャーにシート（スプレッドシートなど）のリンクを載せる場合は、そのシートの共有設定が「リンクを知っている全員」になっていないか確認してください。ランチャーのページと `apps.js` は誰でも見られるため、共有設定が「リンクを知っている全員」だと、社外の人もシートを開けてしまいます。共有は社内（thomas-gr.com）か、使う人だけに限定してください。

ランチャーの「経理担当者向け」の表示は案内にすぎず、アクセス制限ではありません。役員経費精算ツールを経理担当者だけに使わせる場合は、ツール側（Apps Script）で利用者のチェックを行ってください。

## 8. 名前・アイコンを変更したときの注意

ランチャーの名前やアイコンを変えた場合、すでにインストール済みの端末では次のようになります。

- **iPhone・iPad**：ホーム画面のアイコンと名前は、追加した時点のまま変わりません。新しい名前・アイコンにするには、ホーム画面のアイコンを削除して「ホーム画面に追加」をやり直してください。
- **Android・PC**：Chrome・Edge が定期的に設定を読み直すため、しばらくすると自動で切り替わります（すぐに変わらない場合は、アンインストールしてからインストールし直してください）。
